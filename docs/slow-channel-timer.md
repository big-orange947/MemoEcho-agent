# 慢通道定时归并

慢通道用于减少普通群聊对工作台的打断。它按会话分别缓冲消息，并使用“数量阈值或时间阈值先到者生效”的规则生成摘要。

## 触发规则

- 默认数量阈值：`10` 条。
- 默认时间阈值：从该会话第一条缓冲消息开始计时 `600` 秒。
- 会话设定集可通过 `digestMaxMessages` 和 `digestWindowSeconds` 覆盖默认值。
- 空文本不会进入缓冲区。
- 快通道消息默认只进入事件历史，不进入慢通道，避免同一消息被即时提醒和摘要重复展示。会话设定集开启 `includeUrgentInDigest=true` 后，快通道消息可作为后续摘要上下文，但不会自行触发阈值。

数量阈值先触发时，运行时会取消该会话的计时器并立刻生成摘要。时间阈值先到时，后台计时器会直接回传摘要到事件中心，即使期间没有新消息也能在工作台中出现。

## 持久化流程

1. Python Runtime 的 `SlowChannelBuffer` 按会话创建异步计时器。
2. 计时器到期后生成摘要和来源事件 ID 列表。
3. Runtime 调用 `POST /internal/events/digests`。
4. event-center 将其保存为 `conversation_digest` 合成事件，状态为 `DIGEST_READY`。
5. 工作台收件箱从普通事件列表读取该合成事件，无需轮询 Python 进程内存。

该摘要事件不会重新派发给 Agent，避免形成摘要再摘要的循环。
