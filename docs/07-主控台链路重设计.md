# 主控台委托链路重设计

> 状态：设计草案（v0.1）
> 本文档定义主控台（工作台）委托任务的链路重构，与 `06-运行时上下文与长期记忆重设计.md` 正交配合：
> 本文档管**流程结构**（调用几次模型、流程怎么走），06 文档管**内容装配**（每次调用喂什么，ContextEnvelope）。

## 1. 背景与目标

主控台委托链路（desktop 命令 → 规划 → 逐步执行）经真实延迟打点（`llm_call_duration` + `http_duration`）确认存在结构性问题：

| 阶段 | 现状 LLM 调用 | 实测 |
| --- | --- | --- |
| 创建 | `resolve_workspace_command_targets` + `plan_workspace_command` + N×`compile_task`（2+N 次） | 命令解析 10-45s+ |
| 执行 | 委托图 assess→plan→review→select→evaluate（3-7 次串行） | 单步 15-100s+ |

普通 QQ 消息（"帮我记得带合同"）也曾被卷入委托图，单条 122s 且无回复。

目标：
- 创建阶段 LLM 调用 2+N → **1 次**（单次结构化规划 + schema 校验）
- 执行阶段单步 3-7 → **1-2 次**（单次 decide + 规则护栏 + 按风险分级审查）
- 模型路由：判断/规划/审查走快速模型（非思考），生成文本保留思考模型
- 普通消息不进委托图（仅主控台命令/明确任务上下文进入）
- 预留长期记忆注入点（`graphMemories`），与 06 文档 P-C 平滑衔接

## 2. 目标架构

```
┌─ 创建阶段：单次规划 ────────────────────────────────┐
│  命令 + 联系人候选 + 线程历史 + [graphMemories]     │
│        │                                            │
│        ▼                                            │
│  Planner 单次调用（fast 模型）                      │
│  输出完整结构化契约 JSON：                          │
│  { title, workflowType,                            │
│    steps: [{stepKey, role, instruction,            │
│              target, dependsOn, requiredFacts,     │
│              producesFacts}] }                     │
│        │                                            │
│        ▼ 规则校验（联系人白名单 / 依赖合法性）       │
│  直接落库 delegated_workflow + delegated_task       │
└────────────────────────────────────────────────────┘

┌─ 执行阶段：最小决策图 ──────────────────────────────┐
│  build_context（DB/API，非 LLM）                    │
│    → ContextEnvelope（含 timeline / workflowFacts / │
│       verifiedMemories / graphMemories[预留]）       │
│        │                                            │
│        ▼                                            │
│  decide 单次调用（fast 模型）                       │
│  输出 { action, message, requiresReply,            │
│          pendingConditions }                       │
│        │                                            │
│        ▼ 规则护栏（非 LLM，reply_guard）            │
│  内部术语 / 越权 / 敏感检查                          │
│        │                                            │
│        ▼ 按风险分级审查                              │
│  低风险(普通文本) → guard 通过即放行                │
│  高风险(资产/付款/承诺) → 统一审查服务（fast 模型）  │
│        │                                            │
│        ▼ finalize（写回 / 发消息 / 激活下一步）      │
└────────────────────────────────────────────────────┘
```

## 3. 关键设计决策

### 3.1 创建：单次规划替代 2+N 次

- 一个 Planner 调用同时产出：目标会话解析 + 父工作流计划 + 每步契约。
- **schema 校验**：Pydantic 严格校验输出；不合法 → 重试一次（fast，成本低）→ 仍失败走澄清。
- **规则兜底**：联系人白名单、步骤依赖合法性、target 会话授权全部在代码里二次校验，模型不可信。
- 线程历史（threadHistory）继续注入，保持多轮连续（P3 成果不丢）。

### 3.2 执行：单次 decide + 规则护栏

- 委托图精简为：build_context → decide → guard → 分级审查 → finalize。
- decide 只做"判断"（动作 + 消息 + 条件），输出 JSON；不再拆 assess/plan/select 多次调用。
- 工具执行（发消息/读历史）由 guard 和 finalize 处理，不进模型调用链。

### 3.3 审查：统一服务 + 风险分级

- 设定集链路（`ReviewAgent`）与委托链路（`_review_react_candidate`）**合并为统一审查服务**。
- 审查输入统一瘦身：授权边界（`compile_review_boundaries`）+ 候选引用来源 + 最近 5-6 条 timeline。
- 分级：
  - 低风险（普通文本、闲聊）：guard 通过即放行，不调审查模型。
  - 高风险（涉及资产/付款/承诺/现实执行）：调统一审查服务（fast 模型）。
- 重试：不再"3 次不过强制放行"；改为转人工或待确认草稿（按 06 文档安全原则）。

### 3.4 模型路由

| 调用 | 模型 |
| --- | --- |
| Planner（创建） | fast（非思考） |
| decide（执行判断） | fast（非思考） |
| 审查（分级） | fast；高风险可配思考模型 |
| 生成回复文本 | 思考模型（质量优先） |

### 3.5 普通消息防护

- 仅当 `event_type == desktop_command` 或存在明确任务上下文（会话级 ACTIVE 任务 + 控制事件）才进入委托图。
- 普通 QQ 消息一律走 SocialAgent 快速链路（不在 handle_event 里因误判进入委托图）。

## 4. 长期记忆注入预留（与 06 文档衔接）

- `ContextEnvelope` 增加 `graphMemories` 字段（06 文档 §7.1），本轮先定义空结构。
- 注入点（06 §6.2 检索触发点）：
  - Planner 规划时：检索目标联系人的关系/偏好记忆。
  - decide 决策时：检索任务相关事实。
  - 审查核对时：候选引用需记忆证据。
- P-C（06 文档）打通后直接填入，不需要改流程结构。

## 5. 实施分期

| 阶段 | 内容 | 收益 |
| --- | --- | --- |
| P1 | fast 模型通道（`OPENAI_FAST_MODEL`，`generate_reply(fast=...)`） | 判断类调用立即变快 |
| P2 | 创建阶段单次规划 | 创建 2+N → 1 次 |
| P3 | 执行阶段 decide 精简 + 预留 graphMemories | 单步 3-7 → 1-2 次 |
| P4 | 统一审查服务 + 风险分级（含 06 P-C 记忆注入） | 审查瘦身 + 记忆生效 |
| P5 | 普通消息防护 + 状态机简化 | 防误判 |

P1-P3 只改 Python 侧；event-center 调度器 / DB 表 / outbox 机制保留不动。

## 6. 风险与权衡

| 风险 | 对策 |
| --- | --- |
| 单次规划输出复杂易错 | Pydantic schema 校验 + 失败重试 + 规则二次校验 |
| decide 一次出决策+消息，审查不过要重来 | decide 输出带审查标记；高风险才触发审查，低风险 guard 放行 |
| 快速模型判断质量 | 核对/规划类任务适合 fast；高风险审查可保留思考模型 |
| 合并审查影响现有行为 | 保留 STRICT_HANDOFF / AUTO_REWRITE 语义，映射到新分级 |
| 普通消息误入委托 | 事件类型 + 任务上下文双重门控 |

## 7. 验收标准

- 创建命令：从当前 2+N 次 LLM 降到 1 次；命令解析 < 5s。
- 单步执行：decide + 低风险放行 ≤ 2 次 LLM；单步 < 20s。
- 全量 pytest 通过；真实 QQ 消息（普通聊天）不再被卷入委托图。
- 记忆：ContextEnvelope.graphMemories 字段就绪，P-C 可直接注入。
